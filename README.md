# Git Trend Journal

[**공개 사이트 미리보기 ↗**](https://starzzangna.github.io/github-trend-journal/)

GitHub Trending의 Today / Week / Month 상위 10개 프로젝트를 한국어 보고서로 자동 생성하는 GitHub Pages 블로그입니다. 프로젝트별 용도·활용 제안과 공식 README의 시작 절차를 함께 제공합니다. 기본 분석은 무료 규칙 기반이며 선택적으로 유료 AI 해석을 추가할 수 있습니다. 서버, 외부 DB, npm 의존성은 없습니다.

## 아키텍처 재검토

[분석 품질 개선 아키텍처 검토](docs/architecture-review.md)에 현재 수집·분석·발행 구조, 최신 데이터의 분석 공백, 근거 중심 분석을 위한 책임 분리와 단계별 구현안을 정리했습니다. 이 문서는 설계안이며, 아래 실행·운영 설명은 현재 구현을 기준으로 합니다.

## 실행

Node.js 22 이상(권장 24)만 필요합니다. `npm install`은 필요 없습니다.

```sh
node scripts/collect.mjs
node --test
node scripts/build.mjs
node scripts/serve.mjs
```

로컬 개발 미리보기: [http://127.0.0.1:4173](http://127.0.0.1:4173) (위 서버를 실행한 컴퓨터에서만 접속할 수 있습니다.)

## 프로젝트 활용 분석

### 출처·근거와 상태 분리

`sources`에는 문서 경로·파일 SHA·조회 시각·원문 URL을, `evidence`에는 근거 ID·출처 ID·절 제목·절 시작 행·짧은 원문 발췌를 저장합니다. 기능·환경 해설은 `kind: interpretation`과 `evidenceIds`로 근거를 참조합니다. 파일 SHA는 조회한 내용의 식별값이며 원문 링크가 해당 버전에 고정됐다는 뜻은 아닙니다. 원본 README 전체는 저장하지 않습니다.

문서 조회 상태 `document.status` (`available` / `unavailable`)와 분석 품질 `quality.status` (`complete` / `partial` / `unavailable`)는 별도로 관리합니다. 용도 분류·핵심 기능 근거·시작 경로·해결 문제·입력·출력·도입 조건이 모두 있으면 화면에 **기본 항목 충족**, 일부가 없으면 **부분 분석**과 미확인 항목을 표시합니다. 이는 추출 범위의 확인이며 심층 분석·성능 검증을 통과했다는 뜻은 아닙니다. 기존 `status: ready`는 호환용 처리 상태로 유지합니다.

현재 형식은 `schemaVersion: 2`, 분석기는 `analyzerVersion: 8`입니다. 이전 분석기 3·4·5·6·7도 빌드할 수 있습니다. `node scripts/collect.mjs`를 실행하면 구형 분석을 문서 재조회로 갱신하며 발행 키·최초 발행 시각·기존 장부는 보존합니다. 새로운 기간이면 기존 발행 정책대로 해당 기간도 처리합니다. 근거 원문이 없는 구형 JSON에서 발췌를 추측해 만들지는 않습니다. 문서 조회가 실패하면 이전 분석·출처·품질을 보존하고 `document.status: unavailable`, `stale: true`로 표시한 뒤 다음 수집에 재시도합니다.

`scripts/evidence.mjs`가 근거 추출과 품질 판정을, `scripts/contracts.mjs`가 새 형식의 참조 관계와 상태 일관성 검사를 담당합니다. 출처 없는 기능·환경·문제·입출력 해설이나 잘못된 품질 상태는 저장·빌드 전에 거부합니다. 별도 환경 변수나 의존성은 추가하지 않았습니다. 연결 문서는 아래에 설명한 같은 저장소의 제한된 범위만 추가 수집합니다.

### 프로젝트 고유 설명 (2단계 구현)

`scripts/profiles.mjs`에서 디자인 시스템, 물리 시뮬레이션, 개인 재무, 웹 데이터 수집, 브라우저 자동화, 지식 그래프, Git 워크트리, 모델 추론·서빙, 백엔드 플랫폼, 고객 관리 등으로 분류 범위를 넓혔습니다. 저장소 설명은 분류 후보의 우선순위에만 사용하고, README의 문장·제목으로 용도를 뒷받침할 때만 확정합니다. 후원·기여 안내·로드맵이나 코드 예시만으로는 분류하지 않습니다.

`scripts/project.mjs`는 `article.project`에 해결 문제·입력·출력·도입 조건을 기록합니다. 문서의 Input/Output/Problem 절을 우선하고, 없으면 해당 용도에서 입력·출력 역할이 드러난 문장·사용 예를 찾아 제한된 한국어 해설과 연결합니다. 원문의 목적·요구 버전·세부 조건은 원문 언어로 유지하며 자유 번역이나 실행 검증으로 소개하지 않습니다. 같은 분류여도 각 프로젝트의 실제 문장과 명령 예를 사용합니다. 문서에 역할이 없으면 빈 항목과 미확인 상태를 남깁니다.

설치 하위 절은 부모 경로를 함께 저장합니다. 조건의 `scope`는 `required`(해당 경로의 요구사항), `optional`(선택 경로), `not-required`(필수가 아님), `mentioned`(단순 언급)로 구분합니다. 도입 경로 하나의 요구사항을 전체 프로젝트의 필수 조건으로 확대하지 않습니다. 사용 예에서만 확인한 입출력은 `exampleOnly: true`, 근거는 `kind: example`로 기록하고 화면에 실행 미검증을 표시합니다. 코드·명령은 실행하지 않습니다.

같은 분석기 버전도 다시 분석하려면 `node scripts/collect.mjs --refresh-analysis`를 실행합니다. 이미 처리한 기간의 장부·최초 발행 시각은 유지하며, 새 기간은 기존 정책대로 처리합니다. README API가 403·429를 반환하면 이전에 확인한 해당 저장소의 공개 파일 경로가 있을 때만 `raw.githubusercontent.com` 원문 조회를 시도합니다. 이 요청에는 인증값을 전달하지 않고 원본 바이트로 Git 파일 SHA를 계산합니다. 경로가 없거나 조회에 실패하면 이전 분석 보존·다음 실행 재시도 정책을 따릅니다.

`test/fixtures/project-documents.json`에는 여러 분야의 실제 README 일부를 고정 평가 자료로 보관합니다. 테스트는 네트워크 없이 이 발췌와 합성 문서로 같은 분야의 차이, 다른 분야 동음 용어, 미지원·예정 기능, 요구 버전·선택 경로, 잘못된 근거 참조를 검증합니다.

### 작업 경로별 입출력과 문서 제외 진단 (분석기 8)

입출력은 문서에서 명시한 **특정 작업 경로**를 설명합니다. 팀 가져오기·공유, 외부 에이전트의 스레드 요청·조회, 페이지 제작, 보안 감사 보고서 등의 경로를 프로젝트 전체의 공통 입출력 스키마로 확대하지 않습니다. Home Assistant의 자연어 작업 표처럼 문서의 사용 예를 읽은 경우에는 실행 미검증으로 표시합니다. 문서에 없는 공통 입력·출력은 계속 미확인으로 남깁니다.

추가 문서의 `document.links[].reason`으로 `size-limit`, `http`, `timeout`, `network`, `format`을 구분합니다. HTTP 오류는 안전한 상태 코드만 남기며 응답 본문·내부 오류는 기록하지 않습니다. 크기 상한은 압축된 전송 크기가 아닌 **읽은 본문 바이트**로 적용합니다. 크기 제외는 정상 README 분석과 구분해 표시하고 확인 주기 안에는 불필요한 재시도를 생략합니다. 7일 확인 주기가 지나거나 `--check-documents`를 지정하면 다시 확인합니다. 그때 파일이 상한 안으로 줄어들면 자동으로 수집할 수 있습니다. 나머지 조회 실패는 기존처럼 다음 수집에서 재시도합니다.

Astryx의 `packages/cli/README.md`는 2026-11-12 확인 당시 HTTP 200이었지만 본문이 352,891바이트여서 파일당 250,000바이트 상한을 넘었습니다. 링크 오류로 고치거나 상한을 풀지 않고 **분석 제외**로 원인을 표시하며 README와 정상 조회한 문서의 근거를 유지합니다. 근거가 없는 잘린 본문이나 추정 SHA를 저장하지 않습니다.

### 연결된 공식 문서와 요약 범위 (분석기 7)

`scripts/linked.mjs`는 README에 직접 연결된 **같은 저장소·같은 참조의 Markdown**을 최대 2개 추가 조회합니다. 영문판, 설치·시작·사용 가이드 등을 우선하며 파일당 250,000바이트·15초로 제한합니다. README를 합친 프로젝트당 최대 크기는 750,000바이트입니다. 다른 호스트·저장소·브랜치, 이미지, 기여·라이선스 자료는 제외하며 연결 문서의 링크를 다시 따라가지 않습니다. 외부 공식 문서 사이트의 HTML 전체를 수집하는 기능은 포함하지 않습니다. 인증값은 추가 문서 요청에 전달하지 않습니다.

출처마다 경로·파일 SHA·조회 시각을 기록하고 문서별 절·행·근거 ID를 연결합니다. `document.status`는 README 상태이며 `document.links`는 선택한 추가 문서의 개별 조회 상태입니다. 추가 조회 실패는 README 성공이나 기본 품질을 실패로 바꾸지 않습니다. 읽은 문서만 재분석하며 실패한 문서에서 얻었던 이전 해설을 최신 근거로 사용하지 않습니다. 화면에 추가 문서 확인 실패를 알리고 상세에서 경로별 결과를 표시하며 다음 수집에 다시 시도합니다.

재확인 때 README뿐 아니라 **모든 선택 문서의 SHA**가 같아야 본문을 재사용합니다. 추가 문서만 바뀌어도 다시 분석합니다. 기존 7일 확인 주기를 적용하고 추가 문서 조회 실패가 있으면 다음 수집에서 재조회합니다. 시장 데이터 분석·웹 개발 지침·코드 보안 점검·알고리즘 학습·전통 명반 계산과 구현 계획 작성의 한국어 규칙을 보완했습니다. 과학적·투자적 예측의 정확성이나 실제 실행 성공을 보증하지 않습니다. AI 기본 비활성 상태와 기존 환경 변수·의존성은 유지합니다.

### 한국어 우선 표시 (분석기 6)

`scripts/korean.mjs`는 확인된 동작 유형과 원문 근거로 핵심 동작·입출력·설치 조건의 한국어 요약을 제공합니다. 첫 화면은 핵심 동작 다음에 도입 시 주의점을 보여줍니다. 요구 버전과 필수·선택·필수 아님 범위를 유지하고, 원문은 각 설명의 근거 펼치기에서 읽습니다. 저장소 원문 소개와 공식 시작 절의 명령도 접어 둡니다. 전체 문서의 자동 번역이 아니며 요약 규칙이 없는 항목은 미확인으로 표시합니다. 기술명·파일 형식은 원래 표기를 유지합니다. 키·추가 환경 변수·새 의존성은 필요 없고 AI 기본 비활성 정책도 유지합니다.

### 종합 보고서·재사용·최신성 (3단계 구현)

배포 보고서 검토 후 분석기 5에서는 배지·인기 공지·안내문을 목적 추출에서 제외하고, 프로젝트의 처리 방식·결과·제약을 우선 추출합니다. MCP·플러그인 같은 부수적인 용어만으로 기능 해설을 채우지 않습니다. 입출력에는 실제 문장·사용 예를 표시하고, 핵심 기능은 고정된 범용 해설 대신 원문 설명으로 제공합니다. 긴 문장 발췌와 한국어 검토 질문을 구분하며 자유 번역을 생성하지 않습니다. 핵심 판단도 근거 ID를 연결해 저장·빌드에서 검사합니다. 같은 원문 근거의 기능은 합쳐 반복을 줄입니다. 입력·출력이 문서에 없으면 빈 상태를 유지합니다.

### 종합 보고서·재사용·최신성 (3단계 구현)

`scripts/report.mjs`는 모든 프로젝트 분석 처리 후 같은 발행호의 분야 분포·입출력 확인 범위·공통 항목을 종합합니다. 분류 근거가 있는 항목만 분야별로 세고 미분류도 전체 개수에 포함합니다. 공통 입력·출력·환경은 프로젝트별 근거 ID와 조건 범위를 연결하며, 화면에서 원문을 펼쳐 볼 수 있습니다. 공통 언급을 동일한 필수 조건이나 성능으로 해석하지 않습니다. 부분 분석·문서 확인 실패·이전 분석 사용도 집계하며, 저장·빌드 시 종합 결과가 실제 분석 데이터와 일치하는지 검사합니다.

`scripts/freshness.mjs`는 문서 확인 주기를 기본 **7일**로 관리합니다. 유효한 분석은 최신 보고서 3개에서 찾아 새 발행호·다른 기간에서도 재사용합니다. 별도 장기 캐시나 원문 파일은 저장하지 않습니다. 같은 저장소라도 분류 입력인 설명이 다르면 각 입력에 맞는 분석을 고르며, 실행 중 정상 문서 응답은 재사용합니다.

확인 주기가 지나거나 이전 조회에 실패하면 README를 다시 조회합니다. 문서 SHA·경로·저장소, 분석 입력(이름·설명), 분석기 버전이 같으면 기존 본문·근거·품질을 재사용합니다. SHA·경로·입력·분석기 버전이 달라지거나 강제 분석을 요청하면 본문을 다시 만듭니다. SHA가 없을 때는 일치한다고 간주하지 않습니다. 조회 실패 시 마지막 정상 분석과 성공 시각을 보존하고 다음 실행에 재시도합니다. 미래 시각이나 잘못된 확인 시각도 유효한 캐시로 취급하지 않습니다.

시각은 다음처럼 구분합니다. 기존 분석에서 새 시각 필드가 없으면 당시의 정상 생성 시각인 `checkedAt`을 초기값으로 사용합니다.

- `publishedAt`: 발행호의 최초 발행 시각. 분석만 보완하면 유지합니다.
- `collectedAt`: 새 발행호의 목록 수집 시각. 이전 데이터에 없는 값은 임의로 만들어 넣지 않습니다.
- `usage.sourceCheckedAt`: 마지막 정상 문서 확인 시각. SHA가 같아도 정상 재확인하면 갱신합니다.
- `usage.analyzedAt`: 본문을 생성한 시각. SHA 기반 재사용 시 유지합니다.
- `usage.document.checkedAt`: 최근 문서 확인 시도 시각. 실패한 시도도 기록합니다.
- `synthesis.generatedAt`: 종합 결과·참조 정보가 바뀐 시각. 변화 없는 재실행에서는 유지합니다.

`sourceFingerprint`는 문서 SHA·경로·저장소를, `analysisInputFingerprint`는 분석 입력을 식별합니다. `analysisReused`는 최근 문서 조회에서 SHA 일치로 본문을 재사용했는지 나타냅니다. 화면에는 구현용 지문 대신 문서 확인·본문 분석·종합 갱신 시각을 표시합니다.

```sh
# 확인 주기와 관계없이 문서를 재조회하되 SHA가 같으면 본문은 재사용
node scripts/collect.mjs --check-documents

# 문서 재조회 후 SHA가 같아도 본문을 다시 분석
node scripts/collect.mjs --refresh-analysis
```

환경 변수나 의존성은 추가하지 않았습니다. 주기를 조정하려면 `scripts/freshness.mjs`의 `documentMaxAgeMs`를 변경할 수 있고, 테스트·프로그램 호출에서는 `collectPublication`의 `maxDocumentAgeMs` 옵션을 사용할 수 있습니다. 주간·월간 발행호를 매일 새 목록으로 바꾸는 정책은 도입하지 않았습니다.

### 판단·근거 중심 화면과 접근성 (4단계 구현)

각 프로젝트는 **검토 노트**로 표시합니다. 분석 품질·문서 최신성 다음에 도입 전 판단, 미확인 항목, 해결 문제, 입력·출력을 먼저 보여줍니다. 원문 근거는 해당 설명 옆에서 펼치며, 도입 조건·기능 해설·사용 흐름·공식 시작 경로는 추가 분석에서 선택해 읽습니다. 상세 영역은 기본으로 접어 같은 설명이 반복해서 보이지 않도록 했습니다.

**부분 분석**은 문서에서 추출하지 못한 항목이 있다는 뜻이고, **오래된 분석**은 재조회 실패 또는 확인 주기 초과를 뜻합니다. 둘은 동시에 표시할 수 있습니다. 기본 항목을 충족했어도 확인 주기가 지나면 오래된 분석으로 표시합니다. 색뿐 아니라 상태 이름·미확인 항목·오래된 이유를 함께 제공합니다. 확인 시각이 없거나 미래 시각이면 최신이라고 단정하지 않습니다.

빌드는 문서 확인 주기 `documentMaxAgeMs`를 보고서 파일에 포함하며 화면은 그 값을 사용합니다. 종합 화면의 오래됨 개수는 화면을 그리는 시점 기준으로 계산합니다. 서버가 마지막으로 만든 종합 집계의 시점과 구분하며, 분석 품질이나 발행 시각을 바꾸지 않습니다. 문서 자체를 브라우저에서 재분석하거나 재조회하지는 않습니다.

모바일에서는 입출력과 용도 분포를 한 열로 표시하고 긴 저장소 이름·원문·명령을 줄바꿈합니다. 핵심 링크와 펼치기 컨트롤은 44px 이상의 높이와 키보드 초점 표시를 제공합니다. 본문 건너뛰기 링크는 선택한 기간을 유지하며, Enter·Space로 원문 근거를 펼칠 수 있습니다.

보고서 로딩은 15초 제한을 적용하며 네트워크·응답·파일 형식 오류 때 **다시 불러오기**를 제공합니다. 재시도 중 중복 요청을 막고 로딩 상태를 표시합니다. 성공하면 결과 제목, 재실패하면 재시도 버튼으로 초점을 이어 주되 사용자가 기다리는 동안 다른 컨트롤로 이동했다면 초점을 빼앗지 않습니다. 화면 읽기 도구에 전달할 짧은 상태 안내를 별도 영역에 제공합니다. 잘못된 프로젝트 카드 한 건은 다른 카드 표시를 막지 않도록 처리합니다.

검증은 자동 렌더링·상태 전이 테스트와 브라우저 확인을 병행합니다. 오류 복구의 브라우저 확인에는 공개 보고서를 변경하지 않는 로컬 검증 서버에서 일시 503 응답과 지연 응답을 사용했습니다. 이 검증용 데이터·서버는 배포 산출물에 포함하지 않습니다. 별도 의존성·환경 변수는 추가하지 않았습니다.

`scripts/analysis.mjs`는 README에서 코드 블록·기여 안내·라이선스·후원 내용을 제외하고 관련 기능을 찾아 한국어 해설을 생성합니다. 기능마다 근거가 된 README 절 이름과 원문 링크를 표시합니다. 생물학의 transcription처럼 다른 분야의 동음 용어가 음성 기능으로 오분류되지 않도록 용도 분류를 함께 적용합니다. 미지원 표현은 기능 탐지에서 제외합니다. 설치·시작 관련 절에 나온 실행 환경은 **문서에 언급된 환경**으로 표시하며 필수 조건이라고 단정하지 않습니다.

사용 흐름과 결과 확인 기준은 도구 유형별 분석 제안입니다. README의 하위 절이 대안 설치 경로일 수 있으므로 필수 순서로 취급하지 않습니다. 확인 근거가 없을 때는 그 사실을 표시하고 원문 확인을 안내합니다. 기본 노트는 무료 규칙 기반 자동 정리이며 실제 실행 검증으로 소개하지 않습니다. 선택적 AI 해석은 별도 영역으로 표시합니다. 분석 형식이 갱신되면 기존 최신 글만 보완하며 장부·발행 시각은 유지합니다. 이때 문서 조회에 실패하면 이전 정상 분석을 보존하고 다음 실행에 재시도합니다.

`scripts/usage.mjs`가 GitHub REST API에서 공개 README를 읽어 다음 내용을 생성합니다.

- **어디에 쓰나요:** 저장소 설명과 README 도입부의 키워드로 도구 유형을 분류합니다.
- **이런 분이 살펴보세요 / 활용 예:** 분류에 따른 한국어 해석·제안입니다. 실제 사용자 사례나 지원 기능을 추가 검증한 결과와 구분해 표시합니다.
- **시작 방법:** README의 Quick start / Getting started / Installation / Usage 절 제목, 하위 절 최대 3개, 짧은 원문 명령 블록 또는 문장 발췌를 제공합니다. 임의의 설치 명령을 생성하지 않습니다. 명령은 실행하지 않으며, 문서의 전체 절차 확인 링크를 제공합니다.
- **미확인 처리:** 용도 분류가 불확실하면 미확정으로, 문서가 없거나 호출 제한·네트워크 오류가 있으면 확인 대기로 표시합니다. README 실패가 트렌드 보고서 전체 발행을 막지는 않습니다. 다음 예약 실행에서 실패한 항목만 재시도합니다.

기본 자동 생성은 규칙 기반입니다. 원문 발췌·절 제목·명령 예시는 원문 언어로 표시합니다. README에 실제로 사용한 사례가 있다고 주장하거나 해당 프로젝트가 동작한다고 보증하지 않습니다. 시작 절을 찾지 못하면 공식 README 링크를 제공합니다. 250KB 초과 문서는 자동 분석하지 않습니다.

원본 README는 저장하지 않고 추출한 정보, 원문 SHA, 확인 시각만 **최신 게시물의 프로젝트 항목**에 포함합니다. 기간별 중복 저장소의 문서 응답은 실행 중 메모리에서 재사용합니다. 기존 게시물도 발행 키·발행 시각·장부 개수를 유지한 채 분석을 보완하며, 새 보고서는 유효한 기존 분석을 재사용하고 확인 주기가 지난 문서만 재조회합니다.

기본 경로의 Actions에서는 기본 제공 `GITHUB_TOKEN`을 README 조회에만 추가로 사용하며 별도 유료 키는 필요 없습니다. 로컬에서는 토큰 없이 공개 README를 조회할 수 있고, 필요하면 기존 `GITHUB_TOKEN` 환경 변수를 사용할 수 있습니다. 인증값은 생성 JSON이나 로그에 저장하지 않습니다.

### 선택적 AI 심층 분석 (5단계 구현)

`scripts/ai.mjs`는 문서 SHA와 실제 원문 근거를 사용해 도입 관점·제약과 절충·작은 검증 제안을 추가합니다. 기본값은 비활성입니다. `AI_ANALYSIS_ENABLED=1`, `OPENAI_API_KEY`, 실행당 상한 `AI_MAX_COST_USD`를 모두 설정해야 새 호출을 허용합니다. Actions에는 같은 이름의 변수와 키 secret을 연결했으며 실제 값은 등록하지 않았습니다.

생성과 추가 근거 검토 두 요청의 비용을 먼저 예약하고, 시간·프로젝트 수·응답 크기를 제한합니다. 근거 ID·원문 인용·출력 형식 검사와 별도 모델 검토에서 하나라도 거부되면 후보 본문을 버리고 규칙 분석으로 복구합니다. AI 요청은 자동 재시도하지 않습니다. 모델 검토는 사실 보증이 아니며 AI 성공으로 기본 분석 품질을 올리지 않습니다. 문서·입력 지문이 같은 검증 결과만 재사용하고 오래된 AI는 화면에서 숨깁니다.

[AI 설정·비용 가정·실패 복구·검증 범위](docs/ai-analysis.md)에 설정값과 제한을 정리했습니다. 비용 상한은 실행당 제어이며 계정 전체나 월간 청구 상한은 아닙니다. 현재 가격표는 2026-12-11 09:00 KST부터 새 호출을 차단하므로 운영 전 재검토가 필요합니다. 유료 실호출 없이 모의 API와 브라우저로 검증했습니다.

npm이 있으면 `npm run collect`, `npm run check`, `npm test`, `npm run build`, `npm run preview`도 사용할 수 있습니다. TypeScript를 사용하지 않으므로 별도 타입 검사나 ESLint는 없으며, Node 구문 검사와 동작 테스트로 검증합니다. 수동 환경 변수·토큰 설정은 필수가 아닙니다.

## GitHub Pages 설정

1. 이 폴더의 파일을 **공개 저장소의 루트**에 올립니다. 기본 브랜치는 `main`으로 설정합니다.
2. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다.
3. Actions에서 **트렌드 생성 및 Pages 발행**을 수동 실행합니다. 이후 매일 한국 시간 09:23 예약 실행됩니다.
4. 배포 주소는 `https://<아이디>.github.io/<저장소명>/`입니다. 모든 로컬 자산 경로는 상대 경로여서 프로젝트 Pages에서도 동작합니다.

공개 저장소와 표준 `ubuntu-latest` 러너를 사용합니다. 기본 경로는 유료 AI를 호출하지 않으며 큰 러너, 도메인 구매, 외부 호스팅은 사용하지 않습니다. Pages 배포 산출물 보관은 1일로 제한하며 별도 원본 아티팩트나 캐시를 만들지 않습니다. 무료 제공 범위와 이용 정책은 GitHub의 변경을 따릅니다.

## 발행과 중복 방지

- Today: 한국 날짜마다 한 번 처리합니다.
- Week: 한국 시간 월요일부터의 주를 키로 사용합니다. 처음 실행할 때와 새 주 첫 정상 실행 때 발행합니다.
- Month: 한국 연월을 키로 사용합니다. 처음 실행할 때와 새 달 첫 정상 실행 때 발행합니다.
- 본문의 실질 내용(프로젝트 순위·이름·설명·언어)이 **현재 표시 중인 같은 기간 보고서**와 같으면 생략합니다. 숫자만 변한 경우에도 재발행하지 않습니다. A→B→A처럼 목록이 돌아오면 현재 B와 다르므로 A를 새 발행호로 표시합니다. 과거 장부에 A가 있다는 이유로 생략하지 않습니다.
- 같은 프로젝트가 다른 기간에 등장하는 것은 정상입니다. Today와 Week를 서로 중복 처리하지 않습니다.
- 동일 기간 재실행은 트렌드 목록 수집을 생략합니다. 문서 최신성 검사와 종합 보완은 별도로 수행합니다. 다음 기간에 내용이 달라지면 최신 글을 교체합니다.

`content/publication.json`에는 **최신 글 최대 3개와 발행 장부**만 있습니다. 별도 날짜별 스냅샷, 원본 HTML, 통계 이력, 과거 글 목록은 만들지 않습니다. 장부에는 기간 키, SHA-256 내용 해시, 처리 시각, 상태만 남깁니다. `published`는 보고서 생성 및 배포 대상을 준비했다는 뜻이며, 실제 공개 배포 성공은 Actions의 `deploy` 작업으로 확인합니다. 배포 실패 후 재실행해도 준비된 동일 보고서를 다시 배포하므로 글이 추가 생성되지 않습니다.

Git 저장소 특성상 변경 전 파일은 커밋 이력에 남습니다. 원본을 별도 누적 수집하지 않는다는 뜻이며, Git 이력까지 삭제하는 설계는 아닙니다. 장부는 중복 방지를 위해 계속 유지하며, 배포 파일에는 포함하지 않습니다.

## 분석 범위와 운영

목록과 스타 수는 GitHub Trending 웹 화면에서 수집합니다. 공식 Trending API를 사용한다고 주장하지 않습니다. GitHub 표시 순위를 그대로 유지하며, 그 목록 안에서 언어 분포와 표시 기간 스타 수를 비교합니다. GitHub가 사용하는 기간과 순위 선정 방식은 자체 달력 집계와 같다고 가정하지 않습니다. 인과 분석과 과거 대비 변화는 생성하지 않습니다. 외부 설명은 안전하게 텍스트로 표시하고 링크는 GitHub 주소로 제한합니다.

429·5xx·네트워크 오류는 최대 3회 시도합니다. 세 기간 중 수집이 필요한 작업이 하나라도 실패하면 새 파일을 저장하지 않아 기존 정상 글이 유지됩니다. 예약 실행은 지연될 수 있고, 공개 저장소가 60일 동안 활동이 없으면 예약 워크플로가 비활성화될 수 있습니다. 오류 시 Actions 로그를 확인하고 **Re-run jobs**로 재시도하세요. 장기간 같은 내용으로 커밋이 없다면 예약 활성화 상태도 확인해야 합니다.

GitHub 화면 구조가 바뀌면 파서 수정이 필요합니다. 파서가 프로젝트를 하나도 읽지 못하면 빈 글로 덮어쓰지 않고 실패합니다. 최초 수집 전에는 빈 상태를, 보고서 로딩 실패 시에는 재시도 버튼을 제공합니다. Google Fonts를 사용하며 연결되지 않으면 시스템 글꼴로 표시합니다.

## 설계 결정

Astro 등 프레임워크 대신 정적 HTML/CSS/JS와 Node 내장 기능을 사용했습니다. 화면 1개와 기간 탭 3개인 범위에서 설치·업데이트 의존성을 줄이고 무료 빌드를 단순하게 유지하기 위해서입니다. 종합 보고서는 수치·근거 기반 한국어 템플릿으로 생성하고 선택적 AI 해석은 검증된 근거 묶음에 한정해 별도로 제공합니다. AI에 종합 수치나 성장 원인을 생성시키지 않습니다. 각 유형을 해당 기간에 한 번만 처리해 반복 게시를 줄였습니다.
